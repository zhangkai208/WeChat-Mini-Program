# 🎭「今日人设」小程序 · 开发笔记

> 2026年7月17日 · 从一个想法到朋友扫码玩上，完整复盘
> 输入**名字 + 星座 + 心情**，AI 生成一份带网感的"今日人设 + 运势 + 宜忌"

---

## 一、做的是什么

一个微信小程序，练手**腾讯云开发 CloudBase**，跑通了一条完整的后端链路：

```
手机输入 → 小程序前端 → 云函数 → AI大模型 → 云数据库 → 返回展示
```

**技术栈：**
- 前端：微信小程序原生（WXML + WXSS + JS）
- 后端：腾讯云开发 CloudBase（云函数 + 云数据库 + AI 网关）
- AI：CloudBase AI 网关，hy3 模型，OpenAI 兼容协议

## 二、心路历程：踩过的 7 个坑

这一路最值钱的不是代码，是这些坑——每一个都让我对"云开发"理解深了一层。

### 坑 1：环境到底用 cloud1 还是 zk-...？
- **纠结点**：一开始以为"用 cloud1 = 没用腾讯云开发"。
- **真相**：cloud1 **就是**腾讯云开发环境（微信云开发底层 = 腾讯云 CloudBase）。
- **最终选择**：用 `zk-d2gcfqw9f402f9607`——这是 AI 小程序成长计划送的 **6 个月免费**环境，比 cloud1（上线 15 天就收费 ¥19.9/月）划算。

### 坑 2：同一个微信，竟然关联了两个腾讯云账号？
- **现象**：报错"公众号 gh_7a37a1d01688 于 2025-12-03 已在腾讯云注册其他账号 100045303193"。
- **原因**：同一个微信，通过**不同产品入口**（CloudBase 试用 vs 微信开发者工具云开发）注册时，被关联到了**不同的腾讯云账号**。
- **解决**：通过"换绑"，把 cloud1 解绑，统一到 zk-... 这一个环境。从此干净了。

### 坑 3：云函数部署报错"请选择一个云环境"
- **现象**：右键上传云函数，提示"请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境"。
- **原因**：要在**父级文件夹**（`cloudfunctions/`）右键绑定环境，而不是在单个云函数文件夹上操作。
- **解决**：右键 `cloudfunctions` 文件夹 → 选择当前环境 → `zk-...`，再上传部署。

### 坑 4：环境变量配置入口找不到
- **现象**：云函数只有"本地调试/云端测试/版本与配置/删除"几个操作，不知道环境变量塞哪。
- **解决**：版本与配置 → `$LATEST` 那行的「配置」→ 里面才有「环境变量」区域。配了 3 个：`AI_URL` / `AI_KEY` / `AI_MODEL=hy3`。

### 坑 5：AI 调用失败：fetch is not defined
- **原因**：云函数运行时是 **Node.js 16**，而全局 `fetch` 要 **Node 18+** 才有。
- **解决**：把 `callAI` 里的 `fetch` 换成 Node 原生 `https` 模块（零依赖，云函数自带）。**关键细节**：`Content-Length` 必须用 `Buffer.byteLength(body)`，否则中文 body 被算短，请求会被截断。

### 坑 6：AI 调用失败：HTTP 404 page not found
- **原因**：CloudBase AI 网关的正确路径是 `/v1/ai/{provider}/{path}`，OpenAI 兼容协议要补 `/chat/completions`。我原来配的 `/v1/ai/cloudbase` 少了最后一段。
- **解决**：`AI_URL` 改成
  `https://zk-d2gcfqw9f402f9607.api.tcloudbasegateway.com/v1/ai/cloudbase/chat/completions`

### 坑 7：Invoking task timed out after 3 seconds
- **原因**：云函数**默认超时只有 3 秒**，但大模型生成一份人设要 5~15 秒，没跑完就被掐了。
- **解决**：版本与配置 → 配置 → 超时时间，从 `3` 改成 `30` 秒。

> 💡 **踩坑方法论**：每个报错都先看**字面意思**——`not defined` 是缺东西，`404` 是路径错，`timed out` 是超时。对症下药，别瞎猜。

## 三、我学到了什么

### 1. 小程序 vs 云开发：两码事（最重要的认知）
- **小程序（前端）**：永久免费、永久存在，只要不违规就一直能用。
- **云开发（后端）**：云函数/数据库/AI 都在这，**6个月免费，到期要付费**。
- **结论**：6个月后云开发到期不续费，小程序**还能打开**，但"生成人设"功能会失效（因为它依赖云函数 + AI）。

### 2. 云函数（Cloud Function）
- 一段跑在云端的 Node.js 代码，不用自己管服务器。
- 用 `wx-server-sdk` 操作云数据库、读环境变量。
- **环境变量**放密钥（如 AI_KEY），代码里只 `process.env.AI_KEY` 读取——**绝不硬编码**。
- 有**超时限制**，调 AI 这类慢操作记得调大超时。

### 3. 云数据库（Cloud Database）
- 文档型数据库，像存 JSON 对象一样存数据。
- 每条记录自动带 `_openid`，**天然按用户隔离**——A 用户只能读到自己的记录。
- 前端用 `wx.cloud.database()`，云函数里用 `cloud.database()`。

### 4. CloudBase AI 网关
- 调用地址：`https://{envId}.api.tcloudbasegateway.com/v1/ai/{provider}/chat/completions`
- **OpenAI 兼容协议**：请求体 `{model, messages, temperature}`，响应体 `choices[0].message.content`——跟调 OpenAI 一模一样，只换地址。
- 用 `Authorization: Bearer {key}` 鉴权。
- 赠送的 AI 资源**只限小程序 SDK 和云函数里消耗**。

### 5. 小程序部署的三档
| 档位 | 谁能用 | 要审核吗 |
|---|---|---|
| 预览版 | 仅开发者本人 | 不用 |
| **体验版** | 加进体验成员的人（≤15） | **不用** ← 我用的这个 |
| 正式版 | 所有人 | 要（审核 + 备案） |

### 6. AI 小程序的合规坑
- 国家规定：面向公众的**生成式 AI 服务必须备案**（网信办）。
- 备案主体一般是**企业**，**个人基本备不了**。
- 所以个人主体的 AI 小程序，**正式发布基本过不了审核**——但**体验版不受影响**，自己和朋友玩完全合法。

## 四、代码是怎么实现功能的

### 数据流全景
```
[手机输入名字]
      ↓
[首页 home.js]  收集输入 → wx.cloud.callFunction('generatePersona')
      ↓
[云函数 generatePersona]
   ├─ buildMessages()   拼 system + user 的 prompt
   ├─ callAI()          用 https 模块调 AI 网关，拿到一段 JSON 文字
   ├─ parseAIJson()     容错解析（去 ``` 包裹、截取 {…}）
   ├─ 存 records 集合   db.collection('records').add(...)
   └─ 返回 { code:'OK', data:{persona, fortune, yi, ji, luckScore} }
      ↓
[首页 home.wxml]  把 data 渲染成卡片展示
      ↓
[历史页 history.js]  下次进来，从 records 库读自己的历史
```

---

### 1. 全局初始化 — `miniprogram/app.js`
小程序启动时，**告诉微信要用哪个云开发环境**：

```js
App({
  onLaunch() {
    wx.cloud.init({
      env: 'zk-d2gcfqw9f402f9607',  // 云开发环境 ID
      traceUser: true
    })
  }
})
```
> 没这一步，`wx.cloud.callFunction` 和 `wx.cloud.database()` 都用不了。

---

### 2. 首页 — `miniprogram/pages/home/`
**职责**：收集用户输入 → 调云函数 → 展示结果。

**home.js** 关键是 `generate()` 这个异步函数：
```js
async generate() {
  // 1. 校验
  if (!name) { 提示"请输入名字"; return }
  this.setData({ loading: true })

  // 2. 调云函数（核心！）
  const res = await wx.cloud.callFunction({
    name: 'generatePersona',
    data: { name, constellation, mood }
  })
  // 3. 根据返回的 code 判断成功/失败
  if (res.result.code === 'OK') {
    this.setData({ result: res.result.data })  // 渲染卡片
  }
}
```

**home.wxml** 用 `wx:if` 控制卡片显隐，`wx:for` 循环渲染"宜/忌"数组：
```html
<view wx:if="{{result}}" class="card">
  <view class="persona">🎭 {{result.persona}}</view>
  <view wx:for="{{result.yi}}" wx:key="*this">· {{item}}</view>
</view>
```
> 小程序的双向绑定：`bindinput` 把输入存进 `data`，`{{}}` 把 `data` 渲染出来。

---

### 3. 云函数（核心大脑）— `cloudfunctions/generatePersona/index.js`

**① 拼提示词 `buildMessages()`**
把"你是今日人设算命师 + 输出 JSON 格式要求"作为 system，把用户信息作为 user：
```js
return [
  { role: 'system', content: '你是幽默的今日人设算命师…严格只返回JSON…' },
  { role: 'user', content: `名字：${name}；星座：${constellation}；今天：${today}` }
]
```
> Prompt 工程的关键：**明确要求"只返回 JSON"**，并在格式里给出字段示例，AI 才会乖乖输出结构化数据。

**② 调 AI `callAI()`**（用原生 https，绕过 Node16 无 fetch 的问题）
```js
const body = JSON.stringify({ model: process.env.AI_MODEL, messages, temperature: 0.9 })
const u = new URL(AI_URL)
https.request({
  method: 'POST',
  hostname: u.hostname,
  path: u.pathname + u.search,
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer ' + process.env.AI_KEY,  // 从环境变量读
    'Content-Length': Buffer.byteLength(body)          // 字节长度！
  }
}, ...)
// 拿到响应后 return data.choices[0].message.content
```

**③ 容错解析 `parseAIJson()`**
AI 有时不听话，会带 markdown 包裹（```json … ```）或多说话。这里三步兜底：
```js
let t = text.trim()
t = t.replace(/```json|```/g, '')  // 去 ``` 包裹
t = t.slice(t.indexOf('{'), t.lastIndexOf('}') + 1)  // 截取 {…}
return JSON.parse(t)
```

**④ 存库 + 返回**
```js
await db.collection('records').add({
  data: { name, persona, fortune, yi, ji, luckScore, date, createdAt: db.serverDate() }
})
return { code: 'OK', data: parsed }
```

---

### 4. 历史页 — `miniprogram/pages/history/`
从云数据库读自己的历史，按时间倒序，**分页加载**（不限条数）：
```js
const res = await db.collection('records')
  .orderBy('createdAt', 'desc')        // 新的在前
  .skip(this.data.page * 20)           // 跳过已加载的
  .limit(20)                           // 微信单次最多 20 条
  .get()
// onReachBottom 触底时 page+1 再取下一页
```
> 权限"仅创建者可读写"按记录里的 `_openid` 过滤——**前提是记录里 `_openid` 字段有值**（云函数显式写，见坑 8），否则过滤不到自己。

---

### 5. 我的页 — `miniprogram/pages/profile/`
登录态用本地 `Storage` 读取（首页登录时已写入）：
```js
onShow() {
  const userInfo = wx.getStorageSync('userInfo')   // { avatarUrl, nickName }
  this.setData({ userInfo: userInfo || null })
}
```
> 登录信息（头像临时路径 + 昵称）只在本地，**不上云存储**（见坑 10），靠"退出重登"刷新。

## 阶段二：下午迭代（让功能真正能用）

> 上午只是"跑通了 AI"，下午全是加固——历史能看到、不能刷分、登录不冒名、界面不丑。每个改动都对应一个真实踩到的坑。

### 又踩的 3 个坑

**坑 8：历史记录明明有数据，却显示"仅创建者可读写"空状态**
- **现象**：数据库里 records 有记录，历史页却读不出来。
- **根因**：云函数以**管理员身份**执行 `db.add`，**不会自动写 `_openid`**；而"仅创建者可读写"权限是按记录里的 `_openid` 字段去匹配前端用户的 openid——字段是空的，自然匹配不到。
- **关键认知**：
  - 索引里有 `_openid_` ≠ 记录里 `_openid` 字段有值（索引只是系统自动建的查询目录，跟字段值是两回事）。
  - 云函数要给记录打上调用者身份，得 `cloud.getWXContext()` 取出来**显式写**进 data。
- **修复**：[index.js](cloudfunctions/generatePersona/index.js) 开头 `const { OPENID } = cloud.getWXContext()`，add 时 `_openid: OPENID`。

**坑 9：getUserProfile 拿到的是灰头像 + "微信用户"**
- **根因**：微信 2022.10 新规，`wx.getUserProfile` 不再返回真实头像昵称（隐私保护）。
- **修复**：登录页改用 `button open-type="chooseAvatar"` 选头像 + `input type="nickname"` 填昵称。选头像面板里有"使用微信头像"，微信 App 里换了头像，重新登录就更新。

**坑 10：头像到底存哪？**
- 起初想登录时 `wx.cloud.uploadFile` 传云存储、fileID 存本地——但很快发现是夹生方案：fileID 只在本地有，用户找不到，还可能堆成孤儿垃圾；更糟的是微信 App 换了头像，云端还存着旧的，**两边不同步**。
- **最终决定：纯本地存储**——头像临时路径 + 昵称只存 `wx.setStorageSync`，不上云存储。代价是临时文件隔天可能破图（退出重登恢复）、不跨设备；好处是没有云端不一致的坑，"退出重登"天然就是刷新头像。

### 功能加固清单

| 改动 | 怎么做 | 在哪 |
|---|---|---|
| 一天只能生成一次 | 云函数查 `records.where({_openid, date: today})`，命中返回 `DUP_TODAY` + 已有结果 | [index.js](cloudfunctions/generatePersona/index.js) |
| 登录后才能生成 | `generate()` 开头校验 `userInfo`，没有就提示先登录 | [home.js](miniprogram/pages/home/home.js) |
| 历史分页（不限条数） | `skip(page*20).limit(20)` + `onReachBottom` 翻页（微信单次最多 20 条） | [history.js](miniprogram/pages/history/history.js) |
| 我的页美化 | 垂直居中、大头像白边 + 橘色光晕、副标题、淡描边退出按钮 | [profile.wxss](miniprogram/pages/profile/profile.wxss) |

### 这一阶段的认知升级
- **权限隔离不是自动的**：得保证记录里有 `_openid`，"仅创建者可读写"才生效；云函数管理员身份不帮你填，要自己写。
- **小程序的"登录"很受限**：拿不到微信原始头像昵称，只能让用户主动选/填——这是隐私设计，不是 bug。
- **数据该存本地还是云端**：能用本地就别上云端，**云端同步是一致性麻烦的开始**。头像这种"随时会变、且微信是源头"的数据，留在本地最省心。
